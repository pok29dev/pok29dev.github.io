คำเตือนเรื่องข้อมูล (อ่านก่อนใช้ไฟล์)
------------------------------------------------------------------------
ชื่อ-นามสกุล ที่อยู่ เบอร์โทรศัพท์ เลขประจำตัวประชาชน ทะเบียนรถ เลขที่บัญชี
ชื่อบริษัท และเลขที่เอกสารทุกอย่างในไฟล์นี้ เป็น "ข้อมูลสมมติสำหรับฝึกอบรม"
สร้างขึ้นเพื่อการสาธิตโดยเฉพาะ ไม่ได้มาจากและไม่ได้อ้างอิงถึงบุคคล บริษัท
หรือหน่วยงานใดที่มีอยู่จริง ห้ามนำไปใช้เป็นหลักฐานทางกฎหมาย ทางภาษี
ทางบัญชี หรือทางธุรกิจใด ๆ

เลขประจำตัวประชาชนทุกหมายเลขถูกสร้างขึ้นและคำนวณหลักตรวจสอบ (checksum)
ด้วยสูตรมาตรฐาน น้ำหนัก 13,12,11,...,2 คูณกับ 12 หลักแรก ผลรวมหารเอาเศษ 11
แล้วหลักสุดท้าย = (11 - เศษ) mod 10 — บางหมายเลขตั้งใจให้ "ผ่าน" และบางหมายเลข
ตั้งใจให้ "ไม่ผ่าน" ตามที่ระบุไว้ท้ายบรรทัด เพื่อใช้เป็นตัวอย่างคู่เทียบในคลาส


วิธีอ่านเอกสารนี้
------------------------------------------------------------------------
1) บรรทัดที่มีข้อมูลส่วนบุคคลจะกำกับท้ายบรรทัดด้วยลูกศร  ←
2) ข้อความหลังลูกศรบอกว่า "คาดว่าจะถูกจับเป็นค่าแทนอะไร" หรือ "ยังไม่ถูกจับ"
3) [NAME_n] [PHONE_n] [ID_n] [PLATE_n] คือค่าแทน (placeholder)
   ที่โมเดลปลายทางจะมองเห็นแทนค่าจริง
4) เลขลำดับ n คือลำดับที่ระบบตรวจเจอค่านั้น "ในข้อความที่ส่งไปครั้งนั้น"
   จึงไม่ได้ผูกกับหมายเลขในไฟล์นี้ตายตัว — ค่าเดียวกันที่ส่งคนละครั้งอาจได้คนละ n
   ในคลาสให้ยึด "รูปแบบและชนิดที่ถูกจับ" (NAME / PHONE / ID / PLATE) เป็นหลัก
   ไม่ต้องยึดเลข n ให้ตรงกันทุกชุด
5) เนื้อหาแบ่งเป็นชุดบริบท (ชุดที่ 1–8) + ภาคผนวก ก (ชุดตั้งต้นจากคอร์ส)
   + ภาคผนวก ข (กลุ่มตัวอย่างควบคุม) + ตารางสรุปแพตเทิร์น + วิธีใช้ในคลาส

วิธีใช้ในคลาส (ทำตามลำดับ)
========================================================================

 1) เปิดสวิตช์มาสก์ข้อมูลส่วนบุคคล
    เปิดไฟล์ .thclaws/settings.json ในโฟลเดอร์ทำงาน แล้วเขียนค่า
        { "sensitive": { "enabled": true } }
    (ค่าเริ่มต้นคือปิด) หรือถ้าเครื่องที่สอนมีเมนู Settings → Optional features
    → Sensitive-data masking ก็เปิดจากตรงนั้นได้
    ⚠️ ถ้าไฟล์ JSON เขียนผิดรูปแบบ ทุกสวิตช์จะถูกอ่านเป็น "ปิด" เงียบ ๆ
       ให้ตรวจว่าไฟล์เปิดอ่านได้ด้วยโปรแกรมตรวจ JSON ก่อนทุกครั้ง

 2) รีสตาร์ทหรือโหลดหน้าจอใหม่
    สวิตช์นี้ถูกอ่านตอนเปิดระบบ ถ้าเปิดค้างไว้แล้วยังไม่เห็นผล ให้ปิด–เปิดใหม่

 3) ส่งข้อความทดสอบที่กินหลายรูปแบบพร้อมกัน
    พิมพ์ข้อความสั้น ๆ ที่มีทั้งชื่อมีคำนำหน้า เบอร์โทร เลขบัตร 13 หลัก
    ติดกัน และทะเบียนรถ เช่น
        ผู้ติดต่อคือ นายสมชาย ใจดี เบอร์ 081-234-5678
        เลขบัตร 3100600445635 รถเข้าออก ทะเบียน 1กก 1234 กรุงเทพมหานคร

 4) สังเกต "ค่าแทน" ที่โมเดลเห็น
    เปิดมุมมองที่แสดงข้อความที่ส่งออก (หรือดูจาก log/บรรทัดที่ระบบรายงาน)
    จะเห็นว่าค่าจริงถูกแทนด้วย [NAME_n] [PHONE_n] [ID_n] [PLATE_n]
    ⇒ ประเด็นที่ต้องพูด: "ตัวเลขที่ออกจากเครื่องคือ placeholder ไม่ใช่ค่าจริง"

 5) สังเกตเครื่องหมาย 🔓« … » ตอนตอบกลับ
    เมื่อโปรแกรมตอบ ข้อความตอบกลับจะแสดงค่าจริงกลับมาในเครื่องหมาย
    🔓« 081-234-5678 » ⇒ อธิบายว่า "ขาเข้าถูกแทน ขากลับถูกคืนค่า"
    ย้ำว่าเครื่องหมายนี้คือค่าจริงที่ถูกคืนให้ "เฉพาะบนเครื่องคุณ"

 6) ทดสอบ "กลุ่มควบคุม" ในภาคผนวก ข
    ส่งชื่อไม่มีคำนำหน้า (คุณสมชาย) เลขบัตรที่เว้นวรรค และเลขที่
    checksum ไม่ผ่าน แล้วดูว่าไม่มีอะไรถูกแทน ⇒ "ระบบไม่ได้จับทุกอย่าง
    ที่เราเห็นว่าเป็นข้อมูลส่วนบุคคล"

 7) บันทึกผลเป็นตารางเทียบ
    ให้ผู้เรียนจดผลที่เห็นจริงลงช่อง "คาดว่า" แล้วเทียบกับตารางสรุปแพตเทิร์น
    ถ้าต่าง ให้วงช่องนั้นไว้ — นี่คือความจริงของ build ที่ใช้สอน

 8) ปิดสวิตช์เมื่อจบการสาธิต
    อย่าลืมปิดกลับเป็น false เพื่อไม่ให้มีพฤติกรรมมาสก์ค้างอยู่ในงานอื่น
    ที่ผู้เรียนทำต่อในเซสชันเดียวกัน


========================================================================
ข้อควรระวัง (ย้ำทุกครั้งก่อนจบโมดูล)
========================================================================

 - ไฟล์ประวัติการสนทนา (session) บนเครื่องของคุณยังเก็บ "ค่าจริง"
   การมาสก์เกิดที่ชั้นการส่งออกเท่านั้น ⇒ อย่าเข้าใจว่าไฟล์ในเครื่องถูก
   ล้างข้อมูลให้แล้ว

 - การมาสก์ถูก "ข้าม" โดยตั้งใจเมื่อเลือกใช้โมเดลที่รันบนเครื่องคุณ
   เพราะข้อมูลไม่ออกจากเครื่องอยู่แล้ว ⇒ ถ้าสอนด้วยโมเดลในเครื่อง
   จะไม่เห็น placeholder และไม่ควรสรุปว่า "ฟีเจอร์เสีย"

 - ระบบมัลติยูสเซอร์ไม่เปิดใช้ฟีเจอร์นี้ เพราะ placeholder ของผู้ใช้คนหนึ่ง
   อาจถูกแทนค่าด้วยค่าจริงของอีกคนหนึ่งได้

 - ฟีเจอร์นี้เป็นการ "ลดการเปิดเผยข้อมูล" ไม่ใช่ "การรับประกันการปฏิบัติ
   ตาม PDPA" ⇒ ถ้าเอกสารใดห้ามออกจากองค์กรเด็ดขาด อย่านำเข้าแชตที่ต้อง
   ส่งออกไปผู้ให้บริการโมเดล ให้ใช้โมเดลในเครื่องหรือเก็บไว้นอกระบบ

 - ในคลาสให้ใช้ไฟล์ตัวอย่างนี้เท่านั้น ห้ามใช้เอกสารลูกค้า พนักงาน หรือ
   สลิปโอนเงินจริงเป็นวัสดุสาธิต

 - ตัวเลข ชื่อ บริษัท และที่อยู่ทุกอย่างในไฟล์นี้เป็นข้อมูลสมมติสำหรับ
   ฝึกอบรม ไม่ใช่ข้อมูลของบุคคลหรือหน่วยงานจริง
